# Contributing

Thank you for your interest in the work of The Open Browser Company.

This repository holds organization-wide guidelines. Project-specific setup, build steps, and tests live in each project's own repository.

## Before you start

- Search the project's existing issues and pull requests first. Someone may already be working on the same thing.
- For a substantial change, open an issue to discuss the approach before writing code. Small fixes do not need a discussion first.
- Treat a repository's `README.md` and `LICENSE` as the source of truth for how to build it and what license applies.

## Reporting bugs

Open an issue in the affected repository and include:

- what you expected to happen and what happened instead
- the steps needed to reproduce the problem
- your OS, version, and relevant hardware
- logs or screenshots when they help

If the problem might be a security vulnerability, **do not open a public issue**. Follow [SECURITY.md](SECURITY.md) instead.

## Proposing changes

Describe the problem before the solution. Explain who benefits, what alternatives you considered, and what you would leave out. Focused changes are much easier to review than large ones.

## Pull requests

- Keep each pull request focused on one change.
- Follow the conventions already used in the repository.
- Include tests or documentation when the repository has a place for them.
- Describe what changed and why, and link the related issue if there is one.
- Be responsive to review feedback; reviewers are people, not gatekeepers.

## Community

Participation in this organization is governed by our [Code of Conduct](CODE_OF_CONDUCT.md). Please read it before opening issues or pull requests.

Questions about using a project belong in [SUPPORT.md](SUPPORT.md), not in the code of conduct or security process.
