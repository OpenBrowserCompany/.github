# Security Policy

Security matters to everything we build. Please report suspected vulnerabilities privately so they can be investigated before details become public.

## Reporting a vulnerability

Use GitHub's **private vulnerability reporting** for the affected repository if it is enabled. If it is not available yet, contact the maintainers privately at **[SECURITY CONTACT — TO BE PROVIDED BEFORE PUBLISHING]**.

Please do not open a public issue for an unpatched vulnerability, and do not include exploit details in a public issue, discussion, or pull request.

A useful report includes:

- the affected project, version, or commit
- a description of the issue and its potential impact
- steps to reproduce it, including a minimal example if possible
- any known mitigations or workarounds

We aim to acknowledge reports promptly, keep you informed as we investigate, and agree on a disclosure timeline with you before publishing details.

## Supported versions

Support windows are defined by each project's repository. Check the affected repository for its releases and status; this organization does not apply a single blanket support policy across all projects.

## Scope

This policy covers the software maintained by The Open Browser Company. Vulnerabilities in third-party dependencies are best reported to their upstream maintainers, with a private note to us if our use of the dependency makes the issue exploitable.
